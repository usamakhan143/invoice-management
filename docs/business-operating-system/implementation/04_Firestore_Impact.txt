2. NEW COLLECTIONS — PHASE 1 (REQUIRED)
================================================================================

--------------------------------------------------------------------------------
2.1 bosVentures
--------------------------------------------------------------------------------
    Scope:     companyId (required, indexed)
    Purpose:   Strategic business unit registry (NOT CRM businesses)

    Suggested fields:
        id                  string (auto)
        companyId           string
        name                string
        description         string?
        status              "active" | "archived"
        createdAt           Timestamp
        updatedAt           Timestamp
        createdById         string

    Indexes:
        companyId + status
        companyId + name

    Rules:
        read:  canAccessCompanyData(companyId) && bos_venture_view
        write: bos_venture_manage + company match

--------------------------------------------------------------------------------
2.2 bosInitiatives
--------------------------------------------------------------------------------
    Scope:     companyId
    Purpose:   Strategic hub — campaigns, spend, decisions orbit this

    Suggested fields:
        id                  string
        companyId           string
        ventureId           string (FK → bosVentures)
        name                string
        hypothesis          string?
        status              "draft" | "active" | "paused" | "closed"
        startDate           Timestamp?
        endDate             Timestamp?
        closedAt            Timestamp?
        closedReason        string?
        createdAt           Timestamp
        updatedAt           Timestamp
        createdById         string

    Indexes:
        companyId + ventureId + status
        companyId + status + updatedAt

    Rules:
        read:  bos_initiative_view
        write: bos_initiative_manage
        close: bos_initiative_close (or manage)

--------------------------------------------------------------------------------
2.3 bosAttributions
--------------------------------------------------------------------------------
    Scope:     companyId
    Purpose:   Sidecar linking ERP entities to BosInitiative

    Suggested fields:
        id                  string
        companyId           string
        initiativeId        string
        ventureId           string (denormalized for query)
        sourceType          "expense" | "invoice" | "lead" | "manual"
        sourceId            string (expense id, etc.)
        amount              number? (snapshot at attribution time)
        currency            string?
        status              "proposed" | "confirmed" | "locked"
        notes               string?
        attributedById      string
        createdAt           Timestamp
        updatedAt           Timestamp

    Unique constraint (application-level):
        One active confirmed attribution per (sourceType, sourceId) per company
        OR allow split attributions in Phase 2 — Phase 1: one initiative per expense

    Indexes:
        companyId + initiativeId
        companyId + sourceType + sourceId
        companyId + ventureId

    Rules:
        read:  bos_attribution_view
        create/update: bos_attribution_manage
        lock:  bos_attribution_lock (finance)

    CRITICAL: Never write these fields onto expenses collection.

--------------------------------------------------------------------------------
2.4 bosDecisions
--------------------------------------------------------------------------------
    Scope:     companyId
    Purpose:   Minimal decision log (Doc 13 Phase 1 subset)

    Suggested fields:
        id                  string
        companyId           string
        initiativeId        string?
        ventureId           string?
        title               string
        context             string?
        decision            string
        status              "open" | "decided" | "superseded"
        decidedAt           Timestamp?
        decidedById         string?
        createdAt           Timestamp
        createdById         string

    Indexes:
        companyId + initiativeId + status
        companyId + status + createdAt

    Rules:
        read:  bos_decision_view
        write: bos_decision_manage

5. FIRESTORE RULES IMPACT
================================================================================

    Add match blocks following existing pattern:

        match /bosVentures/{docId} {
          allow read: if canAccessCompanyData(resource.data.companyId)
                      && hasBosPermission('bos_venture_view');
          allow create: if canAccessCompanyData(request.resource.data.companyId)
                        && hasBosPermission('bos_venture_manage');
          allow update, delete: if ... same pattern ...
        }

    Implementation note:
        firestore.rules has no hasGranularPermission helper today — rules use
        canAccessCompanyData + role checks. Options:
        A) Mirror permission keys in custom token claims (heavy)
        B) Rules: company access only; app enforces bos_* (current ERP pattern)
        C) Add get(/customRoles/{roleId}) in rules (expensive reads)

    RECOMMENDATION for Phase 1:
        Match existing ERP approach (B): rules enforce companyId tenancy;
        React app enforces bos_* via ProtectedComponent + service guards.
        Document in Risk Register (Doc 07).

================================================================================

    ReportsPage today:
        expenses.where("companyId", "==", companyId) → client filter by date

    BOS enrichment (no new expense queries):
        1. Load expenses (existing)
        2. Load bosAttributions.where("companyId", "==", companyId)
           .where("sourceType", "==", "expense")
        3. Build Map<sourceId, BosAttribution> in bosReportJoin.ts

    Avoid N+1: batch initiative names in one query.
