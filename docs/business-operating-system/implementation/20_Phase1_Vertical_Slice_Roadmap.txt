        • Sidecar law (Doc 04) does not require ExpensesPage changes — only bosAttributions writes

        • Lightweight integration options avoid ExpensesPage entirely:
              — BosInitiativeDetail → "Link expense" (read expenses, write bosAttributions)

          refactor remains unnecessary
        • Full ExpensesPage refactor may still be valuable in Phase 2 for maintainability —
          but it is NOT required to validate BOS or to attribute expenses

    Doc 10 "CONDITIONAL GO" condition 1 (Epic 0 before Stream D) is WAIVED by founder

PHASE 1A — BOS STANDALONE (VERTICAL SLICE 1)
--------------------------------------------------------------------------------

Goal:
    Prove BOS works as an independent module. Zero changes to ExpensesPage.

Deliverables:
    Independent module structure:
        pages/app/bos/                    — all BOS pages
        components/bos/                   — all BOS UI
        services/bos*.ts                  — all BOS services
        hooks/useBos*.ts                  — BOS hooks (permissions, data)
        contexts/BosContext.tsx           — venture/initiative scope (optional)
        layouts/BosLayout.tsx             — BOS section layout (or BosSection wrapper)
        docs/business-operating-system/implementation/bos-module/  — module README (optional, implementation note)

    Entities & features:
        bosVentures, bosInitiatives, bosDecisions collections + services
        BosVenturesPage, BosInitiativesPage, BosInitiativeDetailPage
        BosDashboardPage (BOS-native dashboard — NOT ERP DashboardPage)
        BosNavGroup in Sidebar + App.tsx lazy routes
        bos_* permissions + RoleManagement category
        firestore.rules + indexes for Phase 1A collections
        ActivityLogger bos_* types
        backup v6 for bosVentures, bosInitiatives, bosDecisions

    Explicitly NOT in Phase 1A:
        bosAttributions writes (defer to 1B)
        ExpensesPage, ReportsPage, DashboardPage (ERP) modifications
        AttributionModal tied to expense detail
        Epic 0 / ExpensesPage refactor

Exit criteria (Phase 1A):
    □ Owner creates venture + initiative on staging/production
    □ BosDashboard shows initiative counts / open decisions (BOS data only)
    □ Staff without bos_* sees no Strategy nav; ExpensesPage untouched
    □ npm run build passes
    □ Backup v6 includes bos* collections (no attributions yet if deferred)
    □ 14-day staging soak with zero ERP regressions

    □ Duplicate attribution guard active (R-009)
