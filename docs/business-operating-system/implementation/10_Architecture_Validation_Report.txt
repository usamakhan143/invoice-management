1. EXECUTIVE SUMMARY
================================================================================

The proposed Business Operating System (BOS) architecture is compatible with
the existing production application when implemented as a sidecar layer above
ERP modules. The codebase already provides strong foundations: company-scoped
tenancy, granular permissions, activity logging, finance reports with CSV export,
and mature expense/return/loan modules.

No BOS code exists today. Integration is greenfield for BOS collections and
services, with selective enrichment of ReportsPage, DashboardPage, ExpensesPage
(post-split), Sidebar, and backup tooling.

Critical invariant validated: expenses, leads, invoices, campaigns, and CRM
businesses must NOT receive embedded BOS fields. BosAttribution sidecar is
the correct integration point and matches existing architectural intent.

Recommendation: PROCEED to Phase 1 implementation after completing ExpensesPage
split (Epic 0) and deploying Firestore rules/indexes before client writes.

4. KEY FINDINGS
================================================================================

4.1 What already exists and supports BOS
    • Expenses with returns → investment numerator/denominator for initiative ROI
    • ReportsPage + csvExport → enrichment target without rebuild
    • campaigns + Lead.campaignId → future BosCampaignLink anchor (P2)
    • Lead.status funnel stages → future BosFunnelStageEvent (P2)
    • activityLogger + activities collection → audit trail for BOS actions
    • config/permissions + customRoles → bos_* rollout path
    • companyId.ts / expenseCompanyScope → identical tenancy for bos* collections

4.2 What must be created (Phase 1 minimum)
    • Collections: bosVentures, bosInitiatives, bosAttributions, bosDecisions
    • Services: bosVentureService, bosInitiativeService, bosAttributionService,
      bosDecisionService
    • Pages: BosVenturesPage, BosInitiativesPage, BosInitiativeDetailPage
    • Components: AttributionModal, InitiativeBadge, report join utility
    • Permissions: bos_* namespace (~12 keys for P1)

4.3 What must never be modified
    • expenses document schema
    • Staff expense create/edit form (Option C)
    • CRM businesses collection (NOT BosVenture)
    • campaignService / Campaign entity as initiative replacement
    • balanceIntegrityService and integrity report tab
    • resolveCompanyIdForUser semantics

4.4 Highest-risk gap
    ExpensesPage at 3,190 lines with inline Firestore — adding attribution UI
    without prior split violates safe integration. Epic 0 is a hard gate.

4.5 Naming collision (Doc 10)
    Validated in codebase: businessService.ts and businesses collection serve
    CRM customer sub-entities. BosVenture requires separate bosVentures collection.
    No code today uses "venture" terminology — clean namespace available.
