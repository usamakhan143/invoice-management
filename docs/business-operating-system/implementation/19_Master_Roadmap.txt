SECTION 6 — ROLLBACK STRATEGY
================================================================================

Principle: BOS is additive. ERP must keep working if BOS is disabled or removed.

Reference risks: Doc 07 R-001, R-005, R-008


--------------------------------------------------------------------------------
6.1 ROLLBACK LEVEL 1 — APP ONLY (preferred, minutes)
--------------------------------------------------------------------------------
Trigger:
    • UI regression on Expenses/Reports/Dashboard
    • Console errors on staff paths
    • BOS pages broken but ERP healthy

Action:
    1. Redeploy previous app build (pre-BOS git tag / hosting rollback)
    2. Leave firestore.rules and bos* data in place (harmless if app not writing)
    3. bos* collections remain; no ERP impact

Recovery: Fix forward in dev; re-deploy when BC passes

Data impact: NONE on expenses, leads, invoices


--------------------------------------------------------------------------------
6.2 ROLLBACK LEVEL 2 — RULES TIGHTEN (hours)
--------------------------------------------------------------------------------
Trigger:
    • Cross-company access suspected (R-014)
    • Unauthorized bos* writes

Action:
    1. Deploy emergency rules: deny all writes to bos* except owner UID
    2. Redeploy Level 1 app rollback if needed
    3. Audit activities collection for bos_* events
    4. Fix rules bug; redeploy corrected rules before re-enabling writes

Data impact: BOS writes paused; ERP unaffected


--------------------------------------------------------------------------------
6.3 ROLLBACK LEVEL 3 — BOS DATA QUARANTINE (days — last resort)
--------------------------------------------------------------------------------
Trigger:
    • Incorrect attributions at scale
    • Backup corruption

Action:
    1. Level 1 + Level 2
    2. Export bos* collections for forensic backup
    3. Delete erroneous bosAttributions docs (NEVER delete expenses)
    4. Restore bos* from last good backup v6 if needed
    5. Re-attribute manually after fix

Data impact: BOS attribution data only; ERP pristine

NEVER:
    • Delete or migrate expenses collection
    • Strip fields from expense documents
    • Restore v5 backup over v6 without understanding BOS data loss (Doc 08 M-03)


--------------------------------------------------------------------------------
6.4 ROLLBACK DECISION AUTHORITY
--------------------------------------------------------------------------------
    Level 1: Developer or Founder
    Level 2: Founder approval required
    Level 3: Founder + export backup before any bos* deletion
