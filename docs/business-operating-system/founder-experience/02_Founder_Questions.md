# 02 — Founder Questions

**Purpose:** Catalog the questions founders actually ask—and design BOS as an answer engine, not a data entry system.

**Organizing principle:** Founders think in **judgment**, not modules. Every BOS surface should map to one or more questions below.

---

## How to Use This Document

Each question includes:

- **When** it appears in the founder’s rhythm
- **What “answered” feels like** (the outcome, not the metric)
- **What BOS must connect** to answer it honestly

---

## 1. Portfolio & Direction

| Question | When | Answered feels like… | BOS must connect |
|----------|------|----------------------|------------------|
| What am I building? | Daily / quarterly | Clear venture thesis in one sentence | Ventures, initiative hypotheses |
| Am I spread too thin? | Weekly / monthly | Know how many active bets is too many | Initiative count, investment, attention debt |
| Which venture deserves my energy this year? | Annual | Explicit rank, not equal attention | Venture portfolio, outcomes history |
| Are we doing too much incremental work? | Monthly | See % of spend on core vs experiments | Initiative types, attribution |
| What should we stop pretending to care about? | Quarterly | Named kills with reasons | Closed initiatives, lessons |
| Is our strategy still true? | Quarterly | Thesis vs reality, not vanity metrics | Decisions, outcomes, investment trend |

## 2. Initiatives & Bets

| Question | When | Answered feels like… | BOS must connect |
|----------|------|----------------------|------------------|
| Which initiatives are active right now? | Daily | Short list, not a graveyard | Initiative status |
| Which initiative is most important this week? | Weekly | One priority, founder-chosen | Attention queue, decisions |
| Is this initiative working? | Weekly / monthly | Directionally yes/no/unclear | Investment, progress signals, outcomes |
| Should I start this new bet? | Ad hoc | Know opportunity cost vs current slate | Portfolio capacity rules |
| Should I pause this? | Weekly | Clear stall signal + cost of pause | Days idle, spend rate, last decision |
| Should I kill this? | Monthly | Kill threshold met or founder judgment | Budget, ROI direction, lessons |
| Should I scale this? | Monthly | Evidence + capacity to absorb scale | ROI trend, decision history |
| Should I pivot? | Monthly / quarterly | What would change vs current path | Hypothesis, funnel/channel data (future) |
| What did we learn from this initiative? | Close / monthly | One paragraph they’d tell a friend | Closure lessons, decision log |
| Which initiative is silently failing? | Daily / weekly | Surfaced before shame sets in | Spend without progress signals |

## 10. Meta Questions (The Real Job)

These are the questions BOS exists to make **obvious**:

| Question | BOS answer format |
|----------|-------------------|
| **Should I scale?** | “Yes—ROI trending up, budget headroom, capacity OK” or “Not yet—here’s why” |
| **Should I stop?** | “Kill threshold met” or “Still within hypothesis—review date X” |
| **Should I hire?** | “Only if initiative X hits milestone Y” |
| **Should I increase budget?** | “Reallocate from initiative B” or “Wait for 30-day signal” |
| **Which initiative is making money?** | Ranked list with confidence, not raw invoice totals |
| **What is blocking growth?** | One primary bottleneck with evidence |
| **Which decision was correct?** | Decision → expected → actual → verdict |

---

## Question → Product Mapping (Phase Guidance)

**BOS can answer today (vertical slice):**

- Which initiatives exist and their status?
- How much have we invested in this bet?
- What decisions did we make?
- What did we learn when we closed?
- Is spend linked to a strategic initiative?

**BOS must answer for exceptional founder experience (product roadmap, not architecture):**

- Should I scale / stop / pivot? (verdict layer)
- Which initiative is making money? (revenue attribution)
- What is blocking growth? (signal aggregation)
- Which decision was correct? (outcome evaluation)
- What changed since yesterday? (meaningful deltas)

---

## Design Rule

If a founder asks a question and BOS responds with **“go look in another module,”** we failed.

The answer can be “we don’t know yet—here’s what to record today to know in 30 days.” That is still an answer.
